<objective>
Close two Phase 7 gaps surfaced in manual UAT.

Gap 1 — DEFAULT_DARK regression: Phase 4 D-10 set the dark default to #000000, but app.js line 94 still has '111111' and index.html still hardcodes #111111 in the dark-bg colour input, text input, and swatch span. On fresh load with default dark = #111111, AAA on #2563EB has no reachable dark-side variant inside the gamut tolerance, so users see "No accessible pair found" — the symptom reported as "AAA returns no results".

Gap 2 — Ambiguous return shape: findVariantPairs returns `[]` for two semantically distinct cases — (a) input already passes both BGs at the active threshold (D-12, "already accessible") and (b) genuine no-solution. app.js currently distinguishes them with a fragile `prevAltsLen` transition heuristic that misannounces in edge cases (e.g. first load with already-accessible input never announces, threshold toggles can flip the wrong message). Disambiguate with a discriminated return shape.

Purpose: Restore correct AAA behaviour on default load and make the already-accessible vs no-solution branches unambiguous.
Output: Default dark BG flipped to #000000 across runtime sources; findVariantPairs return shape disambiguated; app.js wired to new shape; tests cover both cases.
</objective>
