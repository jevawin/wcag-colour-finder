# Phase 1 — UI Design Contract

> Visual and interaction contract for Phase 1: Colour Engine.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase Note

Phase 1 delivers a pure JS colour maths module with no DOM and no user interface. There are no rendered screens, no interactive elements, and no visible states in this phase. The only "output surface" is the `node:test` terminal output confirming pass/fail.

This UI-SPEC serves two purposes:
1. Establish the project-wide design baseline that Phases 2–5 will inherit.
2. Document the one interaction contract that exists in Phase 1 — the test runner output.

All visual specifications below are **project baseline declarations** — they apply from Phase 2 onwards. Nothing in Phase 1 renders them.

## Colour

Project baseline. REQUIREMENTS.md UI-01 locks the approach: monochrome UI chrome, user's hex as the only colour.

| Role | Value | Usage | Source |
|------|-------|-------|--------|
| Dominant (60%) | #ffffff | Page background, panel surfaces | REQUIREMENTS.md UI-01, CLAUDE.md |
| Secondary (30%) | #f5f5f5 | Input fields, badge backgrounds, light-mode panel frame | Default — one step off white |
| Chrome text / UI lines | #000000 | All UI chrome text, borders, icons | REQUIREMENTS.md UI-01 |
| User colour (accent, 10%) | `var(--user-colour)` | Preview text in panels only — nowhere in UI chrome | CLAUDE.md, CONTEXT.md |
| Destructive | #dc2626 | Not used in Phase 1. Reserved for Phase 2+ error states only. | Default |

Accent (`var(--user-colour)`) reserved for: **preview text rendered inside the light panel and dark panel only**. Never used for buttons, labels, badges, borders, or any UI chrome element.

CSS custom property strategy (to be implemented in Phase 2):
```css
:root {
  --user-colour: #2563eb; /* default — updated via JS on input change */
}
```

Dark panel background: `#000000`. Light panel background: `#ffffff`. These are the defaults from CLAUDE.md and are not user-configurable until Phase 4.

## Phase 1 Interaction Contract

Phase 1 has exactly one interaction: running the test suite.

| Interaction | Command | Expected Output |
|-------------|---------|----------------|
| Run tests | `node --test test/colour-engine.test.js` | TAP output — all tests green, zero failures |
| Test failure | Same command | TAP output with failure details including expected vs actual values |

No browser interaction. No user input. No rendered states.
