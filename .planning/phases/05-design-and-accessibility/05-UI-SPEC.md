## Colour

This tool's chrome is strictly monochrome. The user's entered colour is the sole accent, applied only where specified below.

| Role | Value | Usage |
|------|-------|-------|
| Dominant surface (60%) | `#ffffff` | Light panel background, input backgrounds, badge text on pass badges, find button text |
| Secondary / dark surface (30%) | `#111111` / `#000000` | Dark panel background (`--dark-bg`), body chrome text, find button background, swatch hex labels |
| Page surface | `#f3f3f3` | `body` background (`--surface`) |
| Accent — user colour (10%) | `var(--user-colour)` | Sample text in both panels (`.sample-text` color), `.sample-text:focus` dashed outline tint only (D-03) |
| Error | `#dc2626` (`--error`) | Error border on invalid inputs, error messages, distance warning prefix glyph |
| Pass badge fill | `#16a34a` (`--pass-bg`) | Solid background on pass badges — WILL BE REPLACED by monochrome scheme in Phase 5 (see Badge Spec below) |
| Fail badge stroke | `#111111` | Outline on fail badges — monochrome scheme (see Badge Spec below) |
| Border | `#d1d5db` (`--border`) | Input borders at rest |
| Panel border | `#e5e7eb` (`--panel-border`) | Light panel outer border |

**Accent (`--user-colour`) is reserved for:**
1. `.sample-text` foreground colour (the text being previewed)
2. `.sample-text:focus` dashed outline blended tint (D-03 exception only)

**Accent (`--user-colour`) must NOT appear on:**
- Find button focus outline (change to `--chrome-dark` — D-01)
- `.swatch-btn--selected` ring (change to `--chrome-dark` — D-02)
- `.swatch-pair--selected` ring (change to `--chrome-dark` — D-02)
- Any other focus outline

**Badge colour scheme — Phase 5 change (D-06):**

Replace current coloured pass/fail with monochrome solid vs outline system:

| State | Background | Border | Text / icon colour |
|-------|-----------|--------|-------------------|
| Pass (solid pill) | `currentColor` (inherits chrome: `#111111` on light panel, `#ffffff` on dark panel) | none | panel background colour (inverted) |
| Fail (outline pill) | transparent | `1px solid currentColor` | `currentColor` |

`currentColor` resolves to the panel's chrome colour via CSS cascade (`.panel--light` inherits `#111111`; `.panel--dark` inherits `#ffffff`). This means both panels render monochrome badges without needing separate overrides.

## Interaction Contract

### Focus Specification (A11Y-03)

Unified focus rule for all interactive elements except `.sample-text` (D-09):

```
outline: 2px solid <chrome-colour>;
outline-offset: 2px;
```

Where `<chrome-colour>` is:
- `var(--chrome-dark)` (#111111) — for elements on light surfaces (hex input, find button, light-panel BG input, swatch buttons/pairs in light context, any element on `--surface` or `--light-bg`)
- `var(--chrome-light)` (#ffffff) — for elements on dark panel (`--dark-bg`)

Panel-scoped custom properties already handle this automatically for `.panel--dark` children.

Exception — `.sample-text:focus`:
```
outline: 2px dashed;
outline-color: color-mix(in srgb, var(--user-colour) 50%, transparent);
outline-offset: 2px;
```
This is the only element that may use `--user-colour` in a focus state (D-03).

Error state overrides focus outline colour to `var(--error)` on invalid inputs (existing pattern — retain).

### Focus outline contrast requirement (A11Y-01):

The 2px solid `#111111` outline on `#f3f3f3` (body surface) yields contrast of approximately 13:1 — passes AAA.
The 2px solid `#ffffff` outline on `#111111` (dark panel) yields approximately 21:1 — passes AAA.
Verify during audit that outline colour passes against whichever background it sits on.

### Selected Swatch Ring

`.swatch-btn--selected` and `.swatch-pair--selected`:
```
outline: 3px solid var(--chrome-dark);
outline-offset: 2px;
```
On dark panel context, use `var(--chrome-light)`. Remove `var(--user-colour)` (D-02).

### aria-live Regions

- `#hex-error`: `aria-live="polite"` — already in place.
- `#light-bg-error`: `aria-live="polite"` — already in place.
- `#dark-bg-error`: `aria-live="polite"` — already in place.
- `.badge-area` (both panels): add `aria-live="polite"` — Phase 5 addition (D-08).

Note: badge-area aria-live will announce on every keystroke. This matches existing error-message behaviour. Accept the chatter or add debounce to badge updates (executor's discretion).

### Responsive Breakpoint (D-11)

Stack panels vertically below 700px:

```css
@media (max-width: 700px) {
  .panels {
    flex-direction: column;
    gap: var(--space-lg);
  }
}
```

Replace existing `@media (max-width: 768px)` with `max-width: 700px`. (D-13 — exact breakpoint within 600–800px band.)

Source: CONTEXT.md D-09, D-11, D-13.

## Badge Visual Spec

Badge element: `<span class="badge badge-aa badge--pass">✓ Pass AA</span>`

Structure change: add icon as part of the text content, not a separate `<span>`. Screen readers will read "tick Pass AA" — acceptable; alternatively wrap icon in `<span aria-hidden="true">✓</span>` and keep text separate. Executor should choose the approach that reads cleanest under VoiceOver.

Pill dimensions:
```css
.badge {
  display: inline-flex;
  align-items: center;
  gap: 4px;            /* --space-xs */
  padding: 4px 8px;   /* --space-xs --space-sm */
  border-radius: 4px;
  font-size: 14px;
  font-weight: 400;
  line-height: 1.4;
}

.badge--pass {
  background: currentColor;  /* fills with chrome colour */
  color: /* panel background — light: #ffffff, dark: #111111 */;
}

.badge--fail {
  background: transparent;
  border: 1px solid currentColor;
  color: currentColor;
}
```

Since `currentColor` works relative to the element's own `color`, the executor must ensure `.badge--pass` receives an inverted `color` from its parent context. Recommended approach: set `.panel--light .badge--pass { color: #ffffff; background: #111111; }` and `.panel--dark .badge--pass { color: #111111; background: #ffffff; }` explicitly, avoiding `currentColor` if the cascade is ambiguous.

Icon glyphs: `✓` (U+2713) for pass, `✗` (U+2717) for fail. Unicode text nodes, not SVG (D-05, `<specifics>`).

## Accessibility Audit Targets (A11Y-01, A11Y-02, A11Y-03)

Phase 5 must achieve all of:

1. axe-core DevTools scan returns zero violations (critical + serious) on the live page.
2. Tab order covers: hex input → find button → light BG input → dark BG input → swatch pairs (when visible). No tab traps.
3. VoiceOver reads: hex input label, find button, badge area changes (via aria-live), swatch pair labels.
4. Pass/fail communicated by text + icon, not colour alone (D-05, D-06 — monochrome badges with text labels).
5. All visible focus states use 2px solid chrome-colour outline at 2px offset.
6. Contrast of all chrome text against its background passes AA minimum 4.5:1.

Audit results captured in `05-VERIFICATION.md` as a per-criterion checklist (D-16).

Source: CONTEXT.md D-15, D-16, D-17, REQUIREMENTS.md A11Y-01 to A11Y-03.
