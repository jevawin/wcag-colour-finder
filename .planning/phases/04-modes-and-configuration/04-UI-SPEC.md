## Color

All tokens from existing `style.css` `:root`. Phase 4 introduces `--light-bg` and `--dark-bg` as live-writable CSS custom properties (already declared; currently hardcoded `#111111` for dark — updated to `#000000` per D-10).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--surface: #f3f3f3` | Page background (source: style.css) |
| Secondary (30%) | `--light-bg: #ffffff`, `--dark-bg: #000000` | Panel backgrounds — writable via BG inputs this phase |
| Accent (10%) | `--user-colour: #2563eb` (default) | Swatch selected ring, find-btn focus ring, sample-text colour — user-defined, not a fixed brand accent |
| Destructive / error | `--error: #dc2626` | Invalid hex border, error message text, distance-warning prefix |

Accent reserved for: selected swatch pair ring, find-btn focus outline, `.sample-text` colour. Not for chrome, borders, or headings.

Additional semantic tokens (existing, unchanged):
- `--pass-bg: #16a34a` — Pass badge background only

- `--badge-text: #ffffff` — Badge text only
- `--border: #d1d5db` — Input borders
- `--panel-border: #e5e7eb` — Panel border (light panel only)
- `--chrome-dark: #111111` — All non-panel chrome text, buttons
- `--chrome-light: #ffffff` — Dark-panel chrome text, find-btn text

## Component Inventory

New HTML/CSS components introduced in Phase 4:

### BG Input (per panel)

Placed at the top of `.panel--light` and `.panel--dark`, before the sample text. One instance per panel.

```html
<div class="bg-input-row">
  <label class="bg-input-label" for="light-bg-input">Background</label>
  <span class="hex-prefix">#</span>
  <input id="light-bg-input" class="bg-input" type="text" maxlength="6"
         spellcheck="false" autocomplete="off"
         aria-label="Light background hex colour"
         aria-invalid="false"
         value="ffffff">
  <span id="light-bg-error" class="error-msg" aria-live="polite" hidden>
    Enter a valid hex colour
  </span>
</div>
```

CSS rules:
- `.bg-input-row`: `display: flex; align-items: center; gap: var(--space-xs); margin-bottom: var(--space-md);`
- `.bg-input-label`: `font-size: 14px; font-weight: 400; line-height: 1.4; color: inherit;`
- `.bg-input`: `width: 80px; font-size: 14px; font-weight: 400; padding: var(--space-xs) var(--space-sm); border: 1px solid var(--border); border-radius: 4px; outline: none; font-family: inherit; min-height: 44px;`
- `.bg-input:focus`: `outline: 2px solid var(--chrome-dark); outline-offset: 1px;`
- `.bg-input.input--error`: `border: 2px solid var(--error);` (reuse existing `.input--error` class)

Dark panel override: `.panel--dark .bg-input-label`, `.panel--dark .bg-input` — inherit `color: var(--chrome-light)` from panel. Border uses `--border` unchanged (visible on dark BG).

### Swatch Pair Button

Replaces single `.swatch-btn`. One `<li class="swatch-item">` contains one `<button class="swatch-pair">` and one `<span class="swatch-pair-hex">`.

```html
<li class="swatch-item">
  <button type="button" class="swatch-pair"
          aria-label="Variant pair #2F6FE8 on light, #4E85F0 on dark — click to preview">
    <span class="swatch-pair__half swatch-pair__half--light"
          style="background: #2F6FE8;" aria-hidden="true"></span>
    <span class="swatch-pair__half swatch-pair__half--dark"
          style="background: #4E85F0;" aria-hidden="true"></span>
  </button>
  <span class="swatch-pair-hex">#2F6FE8 / #4E85F0</span>
</li>
```

CSS rules:
- `.swatch-pair`: `width: 96px; height: 48px; display: flex; border: none; border-radius: 4px; cursor: pointer; padding: 0; overflow: hidden;`
- `.swatch-pair__half`: `flex: 1; display: block;`
- Divider between halves: `1px solid rgba(255,255,255,0.4)` applied as `border-right` on `.swatch-pair__half--light`
- `.swatch-pair:focus`: `outline: 2px solid var(--chrome-dark); outline-offset: 2px;`
- `.swatch-pair--selected`: `outline: 3px solid var(--user-colour); outline-offset: 2px;` (mirrors `.swatch-btn--selected`)
- `.swatch-pair-hex`: extends `.swatch-hex` — `font-size: 14px; font-weight: 400; line-height: 1.4; margin-top: var(--space-xs); color: var(--chrome-dark);`

The `.swatch-btn` and `.swatch-hex` classes are retired (replaced by pair variants). Remove or leave unused in CSS — do not remove until Phase 5 design audit confirms.

## Interaction Contracts

### BG Input Behaviour

- On valid input: update `--light-bg` / `--dark-bg` CSS custom property, re-render that panel's contrast ratios and badges, clear pair swatch row (set `hidden`, empty list), schedule URL sync (300ms debounce). Keep last valid BG in memory.
- On invalid input: red border (`input--error` class), `aria-invalid="true"`, show `aria-live` error message. Keep last valid BG applied — panels do not change.
- On blur with empty value: treat as invalid. Show error. Do not reset to default.
- Input type: `text` not `color`. No native colour picker.

### Swatch Pair Click

- Render light panel with `lightHex` at `currentLightBg`
- Render dark panel with `darkHex` at `currentDarkBg`
- Clear selected state from all pair buttons, add `swatch-pair--selected` to clicked button
- Do NOT update `#hex-input` (D-08)

### URL Sync

- Debounced 300ms after any valid input change (foreground hex, light BG, dark BG)
- Write via `history.replaceState(null, '', '#/fg/lightBg/darkBg')` — lowercase hex, no `#` prefix in segments
- On page load: read `window.location.hash`, parse, hydrate inputs and panels. Do NOT auto-run Find.
- Invalid or missing hash: fall back to defaults `fg=2563eb`, `lightBg=ffffff`, `darkBg=000000`

### Find Button (unchanged trigger, updated output)

- On click: run `findVariantPairs(currentHex, currentLightBg, currentDarkBg)`
- Replace swatch row with pair swatches
- If result is empty: show "No accessible pair found" state (see Copywriting)
- Disabled when `#hex-input` is in error state (existing behaviour)

## States

### BG Input States

| State | Visual |
|-------|--------|
| Default | 1px `--border` border, value shows current BG hex (uppercase, no `#`) |
| Focus | 2px `--chrome-dark` outline, offset 1px |
| Invalid | 2px `--error` border, `aria-invalid="true"`, error message visible |
| Valid-changing | Border returns to default, error message hidden, `aria-invalid="false"` |

### Swatch Pair States

| State | Visual |
|-------|--------|
| Default | Two colour halves with 1px hairline divider |
| Hover | No style change (colour tool — swatch hover would misrepresent colour) |
| Focus | 2px `--chrome-dark` outline, offset 2px |
| Selected | 3px `--user-colour` outline, offset 2px |

### Distance Warning (pair variant)

Same `.distance-warning` container, updated copy for pair context. Shown when closest pair's `distance` exceeds `DISTANCE_WARNING_THRESHOLD` (0.12, exported from `variant-search.js`).

## Accessibility Contract

- BG inputs: `aria-invalid`, `aria-live="polite"` error message, explicit `<label>` with `for` — same pattern as Phase 2 main hex input
- Swatch pair buttons: descriptive `aria-label` includes both hex values and context ("on light", "on dark")
- Swatch pair halves: `aria-hidden="true"` (decorative — label on parent button carries meaning)
- Swatch row `<ul>`: `role="list"` and `aria-label="Accessible colour pairs"` (update existing attribute from Phase 3 copy)
- Focus order: BG inputs appear at top of each panel — they appear in DOM before sample text, so tab order is natural
- Minimum touch target: 44px height on BG inputs
