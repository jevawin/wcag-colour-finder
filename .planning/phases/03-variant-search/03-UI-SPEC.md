## Color

All colour tokens sourced from existing `style.css` `:root` block. No new tokens needed.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--surface` #f3f3f3 | Page background |
| Secondary (30%) | `--chrome-light` #ffffff / `--chrome-dark` #111111 | Panels, input area, button |
| Accent (10%) | `--user-colour` (dynamic, default #2563eb) | Swatch selected ring, button focus outline |
| Error / Warning | `--error` #dc2626 | Invalid hex error message |
| Pass badge | `--pass-bg` #16a34a | AA/AAA pass badges |
| Fail badge | `--fail-bg` #6b7280 | AA/AAA fail badges |

Accent (`--user-colour`) reserved for:
- Selected swatch ring/outline only
- Focus outline on the "Find accessible colour" button (mirrors hex input focus pattern)

The swatch backgrounds are the variant colours themselves — they are data, not chrome. Do not use `--user-colour` for swatch backgrounds.

The "Find accessible colour" button chrome:
- Default: background `--chrome-dark` (#111111), label `--chrome-light` (#ffffff). Monochrome — no accent bleed into idle state.
- Focus: `outline: 2px solid var(--user-colour)` — matches hex input focus pattern exactly.
- Hover: background lightened to #333333 (still monochrome). No accent on hover.

Distance warning uses `--error` #dc2626 for the warning icon/prefix text. Warning body text uses `--chrome-dark` #111111.

Source: `style.css` `:root` — all tokens pre-existing. Button pattern derived from hex input focus rule at line 108.

## Component Inventory

### Button: "Find accessible colour"

```html
<button type="button" id="find-btn" class="find-btn">
  Find accessible colour
</button>
```

- Sits on the same row as the hex input, to its right (D-02)
- `display: inline-flex; align-items: center`
- Height matches hex input height (approximately 44px with padding: `var(--space-sm) var(--space-md)`)
- `border-radius: 4px` — matches hex input
- No icon. Label only.
- Disabled state: `opacity: 0.5; cursor: not-allowed` — shown only while search is running (async guard)

### Swatch row

```html
<div id="swatch-row" class="swatch-row" hidden>
  <ul class="swatch-list" role="list" aria-label="Accessible colour variants">
    <!-- repeated -->
    <li class="swatch-item">
      <button
        type="button"
        class="swatch-btn"
        aria-label="Variant #3B82F6 — click to preview"
        style="background: #3B82F6"
      ></button>
      <span class="swatch-hex" aria-hidden="true">#3B82F6</span>
    </li>
  </ul>
  <!-- optional -->
  <p id="distance-warning" class="distance-warning" hidden>
    <span class="distance-warning__prefix" aria-hidden="true">⚠</span>
    These variants are a long way from your original colour — no closer accessible shade exists.
  </p>
</div>
```

- `swatch-row` is `hidden` on load; revealed after first successful search
- List uses `role="list"` to restore list semantics (CSS resets remove them)
- `swatch-btn` is a `<button>` — keyboard accessible, fires `click` event on Enter/Space
- `aria-label` on each button includes the hex value and action description
- `swatch-hex` is `aria-hidden="true"` — the aria-label on the button already carries the hex

### Selected swatch state

The active swatch gets class `swatch-btn--selected`:

- `outline: 3px solid var(--user-colour)`
- `outline-offset: 2px`
- Mirrors the hex input focus style (2px solid). Uses 3px here to differentiate selection from focus.

When the user changes the hex input, the selected state clears (no swatch is selected until they click another).

### Distance warning

Shown when the closest variant's OKLab distance exceeds **0.12** (discretion per D-06).

- 0.12 in OKLab units is approximately the distance between adjacent steps on a typical HSL hue rotation — noticeable but not dramatic. Below 0.12 = imperceptibly close. Above 0.12 = visibly different hue/lightness.
- Warning sits directly below the swatch list, within `swatch-row`.
- Uses `--error` #dc2626 for the `⚠` prefix and the phrase "a long way from". Body text is `--chrome-dark`.

## Interaction Contract

### Search trigger (VAR-01)

1. User clicks "Find accessible colour"
2. Button label changes to "Finding…" and `disabled` attribute set
3. JS runs synchronous search (no async needed — search is CPU-bound pure maths)
4. Swatch row revealed with up to 5 results
5. Button re-enabled, label restored to "Find accessible colour"
6. If all 5 variants exceed OKLab distance 0.12 from original: distance warning shown

### Swatch click (VAR-03)

1. User clicks a swatch button
2. Both panels update — same code path as hex input change (reuse `updatePanels()`)
3. Hex input value does NOT change (D-08)
4. Previous selected swatch loses `swatch-btn--selected` class
5. Clicked swatch gains `swatch-btn--selected` class
6. When user types a new hex, all `swatch-btn--selected` classes clear

### Responsive layout

- Swatch row: `display: flex; flex-wrap: wrap; gap: var(--space-sm)` 
- On narrow viewports swatches wrap naturally — no separate breakpoint rule needed
- Each swatch item: `display: flex; flex-direction: column; align-items: center`
