## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 400 | 1.4 |
| Heading (sample) | 24px | 600 | 1.2 |
| Display (ratio readout) | 20px | 600 | 1.2 |

**Notes:**
- "Heading (sample)" is the `contenteditable` heading rendered inside each panel in the user's chosen colour.
- "Display (ratio readout)" is the contrast ratio number, e.g. "4.52:1", shown below the sample text.
- Body (16px/400) applies to the editable paragraph sample and all UI chrome copy.
- Label (14px/400) applies to badge text (AA/AAA pass/fail labels) and the hex input label.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #ffffff | Page background, light panel background |
| Secondary (30%) | #f3f3f3 | Input area background, max-width container surface |
| Accent (10%) | user's input colour | Sample text in panels only |
| Destructive | #dc2626 | Error border on invalid hex input only |

Accent reserved for: **sample text (heading and paragraph) inside both preview panels**. No other elements use the user's colour. UI chrome stays black and white.

**Panel colours:**
- Light panel background: #ffffff
- Dark panel background: #111111
- Light panel UI chrome (badge text, ratio): #111111
- Dark panel UI chrome (badge text, ratio): #ffffff

**Badge colours:**

Pass state:

| Element | Background | Text |
|---------|------------|------|
| Pass badge | #16a34a | #ffffff |

Fail state:

| Element | Background | Text |
|---------|------------|------|
| Fail badge | #6b7280 | #ffffff |

Both badge states communicate status through text labels ("Pass" / "Fail") not colour alone. Source: REQUIREMENTS.md A11Y-02, applied early.

**Destructive colour** (#dc2626) applies to the hex input border only when the input contains invalid text. The inline error message below the input uses #dc2626 for the text colour.

## Component Inventory

These are the interactive/stateful elements this phase creates:

### Hex Input Field

```
[ # ][ 2 5 6 3 E B         ]
      Enter a valid hex colour   ← error state only
```

- Static `#` prefix rendered as plain text immediately left of `<input>`.
- Input: `type="text"`, `maxlength="6"`, `spellcheck="false"`, `autocomplete="off"`.
- Width: 160px (fits 6 hex characters at 16px comfortably).
- Source: CONTEXT.md D-10.
- Live update triggers on `input` event — validates on each keystroke.
- On valid: remove error border and message, update both panels.
- On invalid: red border (#dc2626, 2px), show inline error message below input. Panels keep last valid colour. Source: CONTEXT.md D-08, D-09.
- Default value on load: `2563EB`. Source: REQUIREMENTS.md INP-03.

### Preview Panels

Two panels side by side. Source: CONTEXT.md D-01.

Layout:
```
┌─────────────────┬─────────────────┐
│  Light panel    │  Dark panel     │
│  bg: #ffffff    │  bg: #111111    │
│                 │                 │
│  [Heading]      │  [Heading]      │
│  [Paragraph]    │  [Paragraph]    │
│                 │                 │
│  4.52:1         │  12.63:1        │
│  [Pass AA] [Fail AAA]  [Pass AA] [Pass AAA]
│  Large: [Pass AA] [Fail AAA]  ...│
└─────────────────┴─────────────────┘
```

- Max-width container: 1200px, centred. Source: CONTEXT.md D-03.
- Panel gap: 32px (xl token).
- Each panel: equal width (50% minus gap).
- Panel border: 1px solid #e5e7eb (light panel visible border); dark panel: no border needed (dark bg is self-defining).

### Editable Text Samples

- Heading: `<h2 contenteditable="true">` — default text: "The quick brown fox"
- Paragraph: `<p contenteditable="true">` — default text: "Designers and developers use accessible colours so everyone can read content clearly, regardless of ability or context."
- Both rendered in the user's chosen colour using a CSS custom property: `--user-colour: #2563EB`.
- Source: CONTEXT.md D-06, D-07.
- On focus: subtle outline (`outline: 2px solid currentColor` at 50% opacity) to indicate editability.
- `contenteditable` caret uses the browser default — no custom styling needed.

### Contrast Badge Row

Appears below the sample text in each panel. Source: CONTEXT.md D-04, D-05.

Structure (two rows):

**Row 1 — Normal text (primary visual weight):**
```
4.52:1  [Pass AA]  [Fail AAA]
```

**Row 2 — Large text (secondary visual weight, 14px label):**
```
Large text:  [Pass AA]  [Pass AAA]
```

- Ratio number: 20px / weight 600 (Display role).
- Normal text badges: 14px / weight 400, padded 4px 8px, border-radius 4px.
- Large text label and badges: 14px / weight 400, opacity 0.75 relative to normal row (lighter visual weight). Source: CONTEXT.md D-05.
- Badge text: "Pass AA", "Fail AA", "Pass AAA", "Fail AAA" — text labels, not icons. Source: REQUIREMENTS.md A11Y-02.

### Responsive Breakpoint

- Below 768px: panels stack vertically (flex-direction: column). Each panel takes full container width.
- Gap between stacked panels: 24px (lg token).
- Input area stays centred, full container width.
- Breakpoint source: Claude's Discretion (CONTEXT.md). 768px is standard mobile/tablet boundary.

## Accessibility Contract

These are in-scope for Phase 2 even though A11Y requirements formally land in Phase 5. They apply to every element built:

- Hex input has `aria-label="Hex colour code"` and `aria-invalid="true"` when in error state.
- Error message is in a `<span aria-live="polite">` so screen readers announce it without a page reload.
- Pass/fail badges communicate state via text, not colour alone. Colour is supplementary. Source: REQUIREMENTS.md A11Y-02.
- `contenteditable` elements have `aria-label` describing their role: `aria-label="Editable heading — light panel"` etc.
- All focus states visible (2px outline minimum). Source: REQUIREMENTS.md A11Y-03.
- Contrast of UI chrome: #111111 on #ffffff = 18.1:1 (passes AAA). Badge text #ffffff on #16a34a = 4.63:1 (passes AA).
